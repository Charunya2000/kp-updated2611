GeisingerConversation Data Storage Overview

Azure Cognitive Search (`geisinger-002`):
Each indexed document represents a node/chunk from a PDF's hierarchical structure.
Key fields:
  - `id`: Unique chunk/node ID
  - `smartnote_id`: Conversation ID (use to filter all chunks for a conversation, the filter on smartnot_id should ALWAYS be set as we always not the smartnote_id)
  - `smart_file_name`: PDF file name
  - `content`: Text content of the chunk
  - `content_vector`: Embedding for semantic search
  - `page`: Page number
  - `title`: Node title
  - `level`: Hierarchy level
  - `parentId`: Parent node ID
  - `root`: Boolean, is root node
  - `children`: Array of child node IDs
  - `createdAt`: Creation timestamp
To retrieve all chunks for a conversation with a specific file, filter by `smartnote_id` which represents the specific document.
Available fields:
  - `id` (string, key, retrievable)
  - `nuid` (string, filterable, retrievable)
  - `smartnote_id` (string, filterable, retrievable)
  - `smart_file_type` (string, filterable, retrievable)
  - `smart_file_name` (string, filterable, retrievable)
  - `content` (string, retrievable)
  - `content_vector` (vector, 1536 dims, searchable via semantic similarity)
  - `page` (int, filterable, retrievable, sortable)
  - `title` (string, retrievable, sortable, searchable)
  - `level` (int, filterable, retrievable, sortable)
  - `parentId` (string, filterable, retrievable)
  - `root` (boolean, filterable, retrievable)
  - `children` (array, retrievable)
  - `createdAt` (date, retrievable, sortable)
Vector search profile: `smartnote-config` (algorithm: hnsw, metric: cosine)


MongoDB (`geisinger-docs` collection):
- Document types:
  - `GeisingerConversation`: Metadata for each conversation (fields: `id`, `fileAName`, `relativeAUrl`, `lob`, `status`, etc.)
  - `HierarchyNode`: Nodes in the PDF structure. Key fields include:
    - `conversationId`: Conversation ID (string)
    - `fileAName`: PDF file name (string)
    - `title`: Node title (string)
    - `level`: Hierarchy level (number)
    - `page`: Page number (number)
    - `children`: Array of child node IDs (array)
    - `parentId`: Parent node ID (string)
    - `type`: Document type (string, always 'HierarchyNode')
    - `content`: Text content (string)
    - `createdAt`: Creation timestamp (date)
    - `nuid`: Node unique ID (string)
    - `smartnote_id`: Conversation ID (string, for cross-source join)
    - `smart_file_category`: Heuristic complexity level for internal purposes only. **NOT TO BE INCLUDED IN ANY FILTERS** (string)
    - `smart_file_type`: File type (string)
    - `smart_file_name`: File name (string)
    - `relativeAUrl`: Relative URL (string)
    - Any additional metadata extracted during parsing
- To retrieve a conversation, query for `GeisingerConversation` by `lob`, `status`, or `id`.
- To retrieve the hierarchy, query for `HierarchyNode` by `conversationId`.



Search Plan Guidance:
- Use Cognitive Search (dataSources value: "CognitiveSearch") for semantic and keyword search over PDF chunks.
- Use MongoDB (dataSources value: "MongoDB") for metadata, hierarchy, and relationship queries.
- Join results using `conversationId`/`smartnote_id` for cross-source enrichment.

Examples of Azure Cognitive Search filter usage (these are examples, don't use these as actual filters.):
- To retrieve all chunks for a conversation:
  `filter: smartnote_id eq '<conversationId>'`  -- this filter should ***ALWAYS*** be added. We always have the conversationId
- To filter by file type:
  `filter: smartnote_id eq '<conversationId>' and smart_file_type eq 'pdf'`
- To filter by page number:
  `filter: smartnote_id eq '<conversationId>' and page eq 3`
- To filter by hierarchy level:
  `filter: smartnote_id eq '<conversationId>' and level eq 1`

IMPORTANT: Do not use title as a filter field.

Supported filter fields: smartnote_id, smart_file_type, smart_file_name, nuid, page, level, parentId, root, createdAt, etc.
Filters use OData syntax and can be combined with semantic search for hybrid queries.
IMPORTANT: smartnote_id will be added to all filters as it represents the file being conversated with so no need to add this to any filter.
